## 背景
私たちは、レガシーの *Ochimono Puzzle Game* を Deno + Lume を用いた Web アプリケーションとしてリメイクします。ゲームは `<div id="game-container"></div>` 内に描画されます。主に以下の二つのアプローチを検討しています: Canvas API を用いたゼロからの実装、または軽量ゲームフレームワーク（Kontra.js、PixiJS など）を採用する方法です。制約事項としては Deno 上での実行、リポジトリをできるだけ小さく保つこと、将来的なメンテナンス性の確保があります。

## 選択肢

### フルスクラッチ
#### 規模の目安
- 開発工数: 約3 人日
- 実行時メモリ使用量: 約10 MB
- 依存ライブラリ: なし

#### メリット
- 完全にカスタマイズ可能
- 依存が無くビルドサイズが最小
- Canvas API のみで学習コストが低い

#### デメリット
- 基本的なゲームループや入力処理を一から実装する必要がある
- 将来的な機能拡張コストが高くなる可能性がある
- 他の開発者が既存フレームワークに慣れている場合、学習ハードルが上がる

### Kontra.js
#### 規模の目安
- 開発工数: 約2 人日
- 実行時メモリ使用量: 約12 MB
- 依存ライブラリ: Kontra.js (≈1 KB)

#### メリット
- 軽量で Deno でも簡単に利用できる
- エンティティ管理・アニメーション・入力ハンドリングが組み込み
- ドキュメントがシンプルで学習コストが低い

#### デメリット
- 機能が限定的で高度なエフェクトやシーン管理が難しい
- プラグインや拡張が少なく、将来性に不安が残る

### PixiJS
#### 規模の目安
- 開発工数: 約2 人日
- 実行時メモリ使用量: 約20 MB
- 依存ライブラリ: PixiJS (≈28 KB)

#### メリット
- 高性能な 2D レンダリングエンジン
- 豊富なフィルタ・エフェクトが利用可能
- 大規模なコミュニティと豊富なプラグインがある

#### デメリット
- ライブラリサイズが大きく、バンドルに影響が出る可能性がある
- API がやや複雑で、シンプルなゲームにはオーバーヘッドになることがある
- Deno での設定に手間がかかる

### Phaser 3
#### 規模の目安
- 開発工数: 約4 人日
- 実行時メモリ使用量: 約30 MB
- 依存ライブラリ: Phaser 3 (≈200 KB)

#### メリット
- 完全なゲームフレームワークでシーン管理・物理エンジン・サウンド等が一式揃う
- 大規模プロジェクトや拡張性に強い
- 豊富なチュートリアルとサンプルがある

#### デメリット
- 学習コストが最も高い
- 余分な機能が多く、シンプルパズルには過剰になる可能性がある
- Deno でのビルド設定が最も複雑

## 考慮事項
- **チームの慣れ**: どのライブラリがチームにとって学習しやすいか
- **将来的な拡張**: 今後高度なグラフィックや複雑なシーンが必要になるか
- **保守性**: 部品が少ないほど依存が古くなるリスクが低い
